# 3d-printer-live（头像打印机）

仓库地址：https://github.com/rhfbgfgfdg999999/3d-printer-live


## 是什么

抖音 / 快手 / TikTok 直播间互动工具：观众**评论、点赞、送礼**后，会在 3D 场景里**打印出自己的头像**，成品转运到传送带上。README 声明完全开源免费，同时推广 600～1800 元的定制开发服务（留有微信号）。

## 效果与功能

- Three.js 渲染 3D 打印现场，头像逐层打印，成品转运到前方横向传送带
- 30 秒无互动自动补测试头像，避免画面空转，真实消息立即优先
- 画质五档：极速低配 / 标准 / 2× / 4× / 8× 影院，选择自动记忆
- 镜头视角可保存（最多 10 个），上次机位自动记忆
- 中英双语版（英文版面向 TikTok）
- 独立场景窗口（纯画面，适合 OBS 窗口采集或第二屏）
- 1080×1920 竖屏直播窗口
- 打印记录面板：昵称、头像、触发方式、大小、分数、时间（分数为娱乐随机分）

## 事件 → 打印规则

| 事件 | 结果 |
| --- | --- |
| 评论（含 666 等所有发言） | 1 张小图 |
| 点赞 | 每赞 1 张小图 |
| 爱心 / 小心心 | 1 张大图 |
| 啤酒 | 2 张大图 |
| 棒棒糖 | 3 张大图 |
| 其他礼物 | 1 张大图 |
| 进场 | 仅语音欢迎，不打印 |

- 优先级：礼物插队（不打断当前打印）> 评论 > 点赞
- 点赞高峰约每 0.4 秒放行一张，防刷屏
- 面板中 8 个开关可控制各事件是否打印、礼物语音、进场欢迎、补位，**默认只有评论打印**

## 架构

- **前端**：Python 起本地 HTTP 服务，访问 `127.0.0.1:8080`（不能直接双击 HTML，浏览器会限制本地 ES modules）
- **数据桥**：Node.js 服务，经 WebSocket `ws://127.0.0.1:8765` 向页面推送事件
- **数据来源**：数据桥从本机浏览器的直播间页面读取弹幕，每 0.3 秒采集一次。优先级：自带可登录的直播间窗口（:9223）→ BrowserOS neo（:9110）→ 已开调试端口的 Chromium（:9222）
- **桌面版**：WebView2 + pywebview 独立应用，使用独立登录配置（需重新登录）
- **依赖**：Python、Node.js、pywebview、WebView2 Runtime

## 启动方式

- `start.bat`：启动打印服务（或 WebView2 桌面应用）
- `start-bridge.bat`：单独启动数据桥，会弹出直播间窗口
- `start-all.bat`：一键启动打印服务 + 直播间窗口（可扫码登录抖音）+ 打印程序窗口
- 直播间地址在「直播连接」面板填房间号或整条链接即可切换

## 头像获取（三层兜底）

1. **协议级直读**：直接解码直播间 WebSocket 协议帧，评论 / 点赞 / 进场 / 关注 / 礼物消息和活跃榜单自带头像，写入本地缓存 `avatar-cache.json`，跨重启、跨房间复用
2. **页面多来源采集**：观众列表、贡献条、进出场记录滚动累积，昵称归一化（去空格和装饰 emoji）后模糊匹配
3. **资料卡补取**：自动点击昵称打开资料卡读取头像，每昵称最多 4 批、每批换 3 个点击位置；无人发言时每 45 秒给最近活跃但无头像的观众补点 2 次
4. 全部失败则生成彩色首字头像

## 要点与注意

- 抖音不公开点赞人，点赞按「本场点赞」增量，在已累积的观众花名册里轮换归属（同一人每轮最多 3 次），保证每个赞都有昵称和头像
- 挂接前已滚过的历史弹幕不打印，只同步头像
- 只读取公开弹幕，不发弹幕、不送礼物
- 依赖抓取直播间页面和协议帧，平台改版可能导致失效；使用前注意平台规则
- 首次使用需关闭旧版 ServerGuard、BridgeGuard 及旧数据桥，避免端口占用

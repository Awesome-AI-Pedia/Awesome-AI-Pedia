# 有了 Kafka 为什么还需要 RabbitMQ？

## 一句话结论

**已经有 Kafka 就先别急着上 RabbitMQ**，能用 Kafka 搞定的就用 Kafka；等真遇到 Kafka 干起来别扭的场景，再单独引入 RabbitMQ。

它俩不是替代关系，是**互补**关系。

---

## 本质区别（打个比方）

- **Kafka = 事件流水账**
  一件事发生了，写进日志，谁想看谁来读，还能回头重看。适合"广播"和"留档"。

- **RabbitMQ = 任务派发中心**
  一个任务扔进去，一堆工人抢着干，干完就销账。适合"派活"和"精细控制"。

---

## 核心差异对比

| 维度         | Kafka                          | RabbitMQ                        |
| ------------ | ------------------------------ | ------------------------------- |
| **设计定位** | 分布式事件流平台（append-only log） | 传统消息代理（队列 + Exchange） |
| **模型**     | 分区日志，**拉模式 (pull)**     | 交换机 + 队列，**推模式 (push)** |
| **吞吐量**   | 极高（百万级/秒）              | 中等（万~十万级/秒）            |
| **消息存储** | 持久化日志，可回溯重放         | 消费确认后删除                  |
| **路由能力** | 弱，只能按 partition key       | 强：direct/topic/fanout/headers |
| **消费语义** | 至少一次                       | 支持最多一次/至少一次/恰好一次  |
| **延迟消息** | 需自己封装                     | 原生支持                        |
| **死信队列** | 需业务代码兜底                 | 原生支持                        |
| **消息优先级** | 不擅长                       | 原生支持                        |

---

## 各自的强项

### Kafka 擅长
- 日志、埋点、监控数据
- 海量事件流（百万级/秒）
- 一个事件多个系统消费
- 消息回放（今天读了明天还能重读）
- 数据同步、CDC、流计算

### RabbitMQ 擅长
- 后台任务队列（发邮件、生成 PDF、图片处理）
- **延迟消息**（30 分钟后自动关闭未支付订单）
- **死信队列**（失败消息隔离，不阻塞正常流程）
- 复杂路由（按 header、topic、优先级精细分发）
- RPC 请求-响应模式
- 多协议支持（AMQP、MQTT、STOMP）

## 什么时候必须再加 RabbitMQ

即便已经有 Kafka，遇到这些场景 Kafka 会很别扭：

1. **延迟任务** —— Kafka 得自己封装，RabbitMQ 开箱即用
2. **死信/重试** —— Kafka 需要业务代码兜底，RabbitMQ 原生支持
3. **复杂路由** —— Kafka 只能按 partition key，RabbitMQ 有 Exchange
4. **单条消息级 ACK** —— Kafka 是按分区批处理的
5. **消息优先级** —— Kafka 不擅长
6. **RPC 请求-响应** —— 需要 correlation ID 的同步/半同步场景
7. **多协议支持** —— IoT、遗留系统对接（MQTT、STOMP）

## 实操建议

### 新系统怎么选

```
第一版：只上 Kafka
    ↓
遇到任务队列类需求实在憋屈
    ↓
再引入 RabbitMQ 补位
```

### 生产上的典型混合架构

Uber、Zalando 等公司的做法：

```
                业务事件
                   ↓
                 Kafka（事件总线）
                   ├── 业务事件、日志、数据流
                   ├── 库存系统消费
                   ├── 数据分析消费
                   └── 风控系统消费

                任务派发
                   ↓
               RabbitMQ（任务分发中心）
                   ├── 发邮件
                   ├── 生成 PDF
                   ├── 延迟关单
                   └── 图片处理
```

- **Kafka** 当事件总线，承载业务事件、日志、数据流
- **RabbitMQ** 当任务分发，承载后台作业、延迟任务、复杂路由

# dsh-next-hint：回合结束后，输入框里推荐「下一句」

> 项目地址：<https://github.com/xiaoshenming/dsh-next-hint>

## 一、这是什么

一轮回答结束、输入框还是空的时候，DSH 输入框的**第一行会自己浮出一句灰字** —— 建议你接下来可以问什么。按 Tab 整句写进草稿，\`Ctrl+Z\` 能撤回，**不会替你发送**。

Claude Code / Claude Desktop 那种 prompt suggestions 的 DSH 版。

\`\`\`text
┌──────────────────────────────────────────────────┐
│ 顺便把失败的那两个用例也修了          Tab 采纳   │
└──────────────────────────────────────────────────┘
\`\`\`

## 二、怎么用

| 时刻 | 表现 |
|---|---|
| 一轮结束 + 草稿为空 | 第一行灰字 + 右侧 \`Tab 采纳\` |
| 光标在输入框，按 Tab | 整句进草稿，光标落在句末，**不发送** |
| 开始打字 | 灰字立刻消失 |
| 切到别的会话 | 灰字清掉 |
| 没配路由 / 超时 / 模型没话说 | 什么都没有（这是正确行为，不弹错误） |

Tab 只在 \`/\`、\`@\` 候选菜单没占用时生效；菜单开着时 Tab 仍然归菜单。

## 三、安装

\`\`\`sh
dsh plugin --profile desktop add "github:xiaoshenming/dsh-next-hint#main"
\`\`\`

或在「设置 → 插件」里添加同一个 git 包，**装完重启一次应用**（插件在启动时进花名册）。更新同理：插件页点更新，或 \`pnpm update dsh-next-hint\`。

配置项（设置 → 插件 → dsh-next-hint，全部有默认值）：开关、provider/model 覆盖、语言、采样轮数、输入字节上限、输出 token 上限、建议长度、超时、每会话冷却。

## 四、亮点

1. **懂上下文** —— 建议由一笔**独立的辅助请求**生成，读的是这个会话最近几轮的真实内容（改了哪个文件、哪个测试红了、停在哪一步），不是「继续？」这种模板。
2. **绝不自动发送** —— 采纳 = 往草稿插入一段普通文本，\`Ctrl+Z\` 可撤回。代码里没有「发送」这条路径。
3. **失败即静默** —— 没配路由 / 模型超时 / 被限流 / 输出不合规 / 跑偏成一大段，一律**没有灰字**，也不弹任何错误，日志里最多一条 warn。
4. **不传会话** —— 浏览器只发 \`sessionId\`，会话内容由宿主在本机进程内读一次，不落盘、不进日志、不出进程边界；非 loopback 来源直接被路由拒绝。
5. **省钱** —— 辅助请求强制走模型**最低推理档**，\`maxOutputTokens\` 默认 128，每会话单飞 + 可配冷却；「草稿空不空、人是不是在打字、现在看的是哪个会话」都在浏览器侧判，所以不会白发请求。
6. **只接官方缝** —— 宿主用 \`ctx.llm\` / \`ctx.sessions\` / \`ctx.webServer.register\`；浏览器挂在官方槽位 \`conversation.composer.dock\`，采纳走 \`input.actions.captureInsertion\` + \`insertText\`。没有 fork 官方包、没有 patch \`.asar\`。

## 五、限制

- 版本 **0.x**，实测环境是 DSH Desktop \`0.2.1-rc.2\`（Windows）。上游一旦改输入框结构，它会先坏 —— 而且是**安静地坏**（没灰字，不报错）。
- 灰字位置依赖编辑器 \`[data-input-scroll]\` 结构与自绘节点；官方目前没有开放行内 hint 的写入口（\`--dsh-composer-hint\` 只给已认领的 \`/命令\` 用）。
- 默认**每轮结束都请求一次**辅助模型（可在设置里加冷却）；不想花这个成本就别开。
- 与同思路的 \`dsh-composer-prediction\` **不要同时装**：会叠出两条灰字，还每轮各花一笔调用。

## 一句话总结

**dsh-next-hint 把「这一轮干完了，下一步问什么」从你自己想，变成一句现成的灰字** —— 看得见、可撤销、绝不替你按回车，失败的时候安静得像没装。
